UML diagrams / REST routes

REST route map

Every operation in Discord's OpenAPI description, grouped by resource. Each group has a class diagram of the DiscordPHP classes that send its routes, with one line per method and route. Routes DiscordPHP does not send yet are gathered in a box of their own. The map follows the latest DiscordPHP release: it is rebuilt when a new version comes out, and every day to catch changes in Discord's description.

Reading the diagrams

A class box lists the methods that send a request, each followed by the route it sends, with :id standing for a path parameter. A method appears once per route it can send. A line with a filled diamond means the class on that end holds the other as a repository, and the label is the property name, as in $guild->members. Repositories reach their routes through freshen() (list), fetch() (get one), save() (create or update) and delete().
